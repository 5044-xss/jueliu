## 1. 用户的核心诉求（最重要，别理解错）

> 用户原话大意：**「不是简洁能用就行。我要的是用起来简洁好用，并且效果要 OK——不能简洁了生成效果不打人，这一段那一段没有严谨性、丝滑性、逻辑性，看起来乱七八糟也不行。」**

拆成可执行的目标：

1. **操作简洁**：用户只需「复制资产提示词 → 外部生成图 → 回传 → 复制分镜提示词 → 按序上传对应图片 → 生成视频 → 回传视频」。
2. **效果好**：人物一致、场景一致、镜头丝滑、内容不穿帮、有逻辑。
3. **严谨**：不能为了少图/少步骤牺牲一致性与连续性。
4. **参考图数量可控**：视频平台能上传的参考图**有数量上限**，这是硬约束（见 5.2）。
5. **别越做越乱**：改动要有清晰的模型和规则，不要东一榔头西一棒子。

**能力边界（必须记住）**：本工作台只保证「提示词 / 约束 / 数据结构」正确，**不保证第三方模型生成的画面**。

## 2. 端到端流程（现状）

```
项目 → 故事 → 剧本 → 资产 → 分镜(段/镜) → 平台提示词 → 外部生成 → 回传视频 → 截尾帧 → 合成(M7未做)
```

用户操作路径：
1. 资产页：每个视角有「复制」和「回传」；角色=四视图，场景=全景，道具=正面。
2. 分镜页：每段「第三方生成」弹窗 → 提示词正文 + 图片清单（`@图N`，按 首帧→场景→角色→道具 排序）→ 平台按序上传 → 生成视频 → 回传。
3. 分镜页：「批量锚定」把上段尾帧设为下段首帧；「AI 修复」修单段连续性。
4. 连续性校验在分镜页展示（warning/info）。

## 3. 当前资产模型（本轮已定，供确认）

| 类型 | 结构 | 参考图 | 备注 |
|---|---|---|---|
| 角色 | 资产 = **锚点（不变项）**；变体 = **造型** | 每个造型 **1 张「四视图」** | 基础造型（如「日常装」）+ 变装（如「酒吧装」）；同场同角色只用同一造型 |
| 场景 | 资产 = **场景锚点**；变体 = 时间/天气 | 每个变体 **1 张「全景」** | 纯空镜、无人物；按地点建资产，name 照抄 location 原文 |
| 道具 | 资产 = **道具锚点**；1 个变体 | 1 张「正面」 | **拆分粒度是当前最大争议，见 5.1** |

**已明确的决策**（新窗口不要重复推翻，除非用户改主意）：
- 角色：锚点与造型分离；一个造型一张四视图（不做多张）。
- 场景：一张干净 16:9 全景空镜，**不拼贴**俯视图/平面图/多区域，不做多视角。
- 连续性规则**内部固定全开**，页面上**不暴露开关**（避免用户误关关键规则）。
- 图片清单编号：`首帧 → 场景 → 角色 → 道具`，同一视角复用同一编号，提示词用 `@图N`。

## 5. 待澄清 / 未决问题（**讨论重点**）

### 5.1 道具拆分粒度（用户明确不满）

**现状（实测项目 `我是苏皖` 067af0d5）**：共拆出 **6 个道具资产**：
`中奖彩票、设计草图、白玫瑰、苏打水、现金、名片`。

**用户观点**：像「现金」「苏打水」「名片」这种**只出现一次**的东西不该单独建资产、更不该占参考图槽位；应该只在那一镜的**动作描述里写一次**即可。否则道具一多，加上角色和场景，参考图根本传不下。

**需要澄清**：
- 判定规则是什么？（出现次数 ≥2？还是剧情关键/需要跨镜外观一致？）
- 一次性道具是否一律不建资产，只在动作里描述？
- 是否要一个**硬上限**（例如每部剧道具资产 ≤ N 个）？

**我的建议（待确认）**：只给「跨镜复用、且外观必须一致」的道具建资产（如中奖彩票、设计草图、挑战卡片）；一次性道具写进动作描述，不建资产、不占槽位。

### 5.2 参考图槽位预算（硬约束）

- 每段图片清单 = 首帧(0/1) + 场景(1) + 角色(每个出场角色 1 张) + 道具(每个被引用道具 1 张)。
- 例：酒吧一场戏，首帧1 + 场景1 + 角色3 + 道具2 = **7 张**。
- **需要澄清**：目标视频平台**最多能传几张参考图**？
- 若超限，优先级怎么砍？（建议：首帧 > 场景 > 角色 > 道具；道具优先砍）

### 5.3 场景参考图形态

- 已定：一张干净 16:9 全景。
- 待确认：一张全景是否足够支撑「场景一致性 + 站位」？还是需要在分镜页单独给一个**站位示意图**（不上传，只给人看）？

### 5.4 造型与场次的对应

- 现状：角色可有多个造型（如苏婉「日常装」「酒吧装」），分镜按场次选造型。
- 待确认：**谁来决定「这场穿哪套」**？剧本通常不写服装。是否需要在资产页给造型标注适用场次（如「酒吧装：用于酒吧相关场次」）？

### 5.5 连续性问题

已修复的误报：
- 地点名与场景资产名不一致 → 放宽匹配。
- 画外音角色无资产 → 跳过。

仍可能出现的**真问题**（模型输出导致）：
- 剧本台词/动作**漏进分镜**（内容覆盖失败）。
- blocking 缺人物节点（如闯入者没进 blocking）。
- 引用错误场景资产。
- 处理方式：单段「AI 修复」（最多 2 次，失败回滚）或重新生成分镜。

待确认：漏台词这种，是接受「修复」流程，还是要求生成时更严格（例如分镜逐条对照剧本，缺一条就整段重生成）？

### 5.6 是否暴露「规则/参数」

- 已定：连续性规则内部全开、不暴露。
- 待确认：是否还有其它内部参数（段时长、每段镜数上限、参考图上限）需要暴露或写死？

## 6. 当前「道具拆分逻辑」完整说明（回答用户）

**提示词层**（`SCRIPT_TO_ASSETS_PROMPT` 第 10 条）：
> basePrompt 写「道具锚点」：材质、颜色、尺寸感与磨损等特征。**只提取剧情中关键、会反复出现的道具**；1 个变体，views 用「正面」。

→ 意图是「只挑关键的」，但**没有硬约束、没有次数判断、没有上限**，全靠模型自觉，所以模型把出现一次的东西也拆了。

**代码层**：
- `saveAssetDrafts()` 原样保存模型返回的所有道具，**不过滤、不设上限**。
- `defaultViewLabels("prop") = ["正面"]`，每个道具自动 1 个视角。

**分镜层**（`SCRIPT_TO_STORYBOARD_PROMPT`）：
- refs 允许 `prop` 引用；**没有限制每镜/每段能引用几个道具**。
- 动作里提到什么，模型就可能引用什么道具。

**渲染层**（`src/lib/render.ts` `buildManifest`）：
- 顺序 `scene → character → prop`，**每个不同的 viewId 占 1 个槽位**。
- 所以道具资产越多、被引用越多 → 参考图清单越长 → 上传压力越大。

**结论**：当前是「模型自由发挥 + 代码不设限」，所以会越拆越细。要根治必须在**提示词规则 + 服务端上限/过滤 + 分镜引用上限**三处一起收（待 5.1 澄清后再动）。
