# 掘漫 · 桌面打包计划（Windows x64 / Electron）

> 目标：把当前 Next.js 项目打包成可售卖的 Windows 桌面应用，具备**离线签名激活**、**手动检查更新**、**内置 ffmpeg**。

## 二、目标架构

Electron 主进程负责**激活校验 + 启动本地 Next 服务器 + 更新检查**；渲染层加载 `http://127.0.0.1:<port>`。数据写入用户目录，不依赖 `cwd`。

```
掘漫.exe (Electron 主进程)
 ├─ 单实例锁 + 激活门禁（未激活 → 激活窗）
 ├─ spawn(process.execPath, [.next/standalone/server.js], { ELECTRON_RUN_AS_NODE: 1 })
 │     └─ Next 服务器（API routes + better-sqlite3 + ffmpeg）
 ├─ BrowserWindow → http://127.0.0.1:<随机端口>
 └─ ipc: 获取机器码 / 激活 / 检查更新
```

关键点：项目含 API Routes、`better-sqlite3` 原生模块、`child_process` 调 ffmpeg，**不能**当纯静态前端加载，必须在 Electron 内跑本地 Next 服务器。

## 三、实施阶段

### Phase 0 — 前置准备
- 仓库已就绪：`origin` = `https://github.com/5044-xss/excavator.git`，`master` 已推送。
- 生成 Ed25519 密钥对：`scripts/gen-keypair.mjs`
  - 私钥仅本地保留，**实际写入 `.gitignore`**（`keys/`、`*.pem`、`license-private*.json`），**绝不入库 / 进安装包**。
  - 公钥内嵌进 App：`electron/license-public.ts`。
- 安装依赖：
  - `electron`、`electron-builder`、`@electron/rebuild`、`concurrently`、`wait-on`
  - 机器码采集：`systeminformation`（或 PowerShell `Get-CimInstance`）

### Phase 1 — 激活码（离线签名，一码一机，永久）
- **机器码**：Windows 取 主板 UUID + CPU ID + 系统盘序列号 → SHA-256 → 取前 16 位，展示给用户。
  - 兜底：虚拟机 / 克隆系统可能取不到序列号或重复；采集失败时回退 `os.machine()+主机名+MAC`，确保稳定非空。
- **激活码格式**：`base64url(payload) + "." + base64url(signature)`
  - `payload = { mid: 机器码, v: 1, issuedAt }`（永久版，无到期字段）。
- **验证**（主进程 `electron/license.ts`，用内嵌公钥 `crypto.verify`）：
  1. 验签 → 2. `payload.mid === 本机机器码` → 3. 通过后写入 `userData/license.key`。
- **门禁**：每次启动先校验；未通过只显示激活窗口（独立 HTML），不启动 Next、不加载主界面。
- **卖家工具** `scripts/sign-license.mjs`：输入用户机器码 → 输出激活码；**不随安装包分发**。
- 换硬件会失效（永久一机码的正常代价），换机由卖家重新签发，写入售后说明。

### Phase 2 — 数据目录与运行环境
- 主进程启动前设 `WORKSPACE_DIR = app.getPath("userData")/workspace`，传给孩子进程（`src/lib/paths.ts:9` 已支持该变量）。
- `app.requestSingleInstanceLock()`：防多开导致 SQLite 冲突。
- **不随包分发** `.env` 与 `workspace/settings.json` 中的 key（`src/lib/settings.ts:19` key 为空时买家在设置页填写）。
- 首次启动引导：提示「请到设置页填入你自己的模型 API Key」。

### Phase 3 — 内置 ffmpeg
- 下载 Windows ffmpeg 静态包，放 `resources/ffmpeg/ffmpeg.exe`（代码只用 ffmpeg，无 ffprobe）。
- electron-builder `extraResources` 打包。
- ⚠️ **路径传递**：Next 服务器跑在 `ELECTRON_RUN_AS_NODE` 子进程里，`process.resourcesPath` 不可靠。由主进程解析 `path.join(process.resourcesPath, "ffmpeg", "ffmpeg.exe")`，通过环境变量 `FFMPEG_PATH` 传给子进程。
- 改默认值：`src/lib/settings.ts:29` 的 `envDefaults()` 读取 `process.env.FFMPEG_PATH ?? "ffmpeg"`；`src/lib/ffmpeg.ts:6` 只是兜底参数，保持。
- 设置页回显实际路径。

### Phase 4 — 在 Electron 内跑 Next（关键难点）
- `next.config.ts` 增加 `output: "standalone"` **和 `serverExternalPackages: ["better-sqlite3"]`**（否则打包器会破坏原生模块）。
- 主进程用 `ELECTRON_RUN_AS_NODE=1` spawn `standalone/server.js`，选空闲端口并通过 `PORT` 传入，就绪后再 `loadURL`。
- ✅ **无需 ABI 重编译（已实测）**：本项目 `better-sqlite3@13` 基于 `node-addon-api`（N-API）预编译分发，跨 Node / Electron 通用；已用 Electron 44 运行时直接 `require` 验证通过。故**不需要 `@electron/rebuild`**。
- 仍需在 electron-builder 里 `asarUnpack` 原生 `.node`（`**/node_modules/better-sqlite3/**`）。
- ⚠️ **Next 软链接**：Next 会为 external 包生成指向仓库根 `node_modules` 的**绝对软链接**（`.next/standalone/.next/node_modules/better-sqlite3-<hash>`），而根 `node_modules` 不入包 → 打包会失败、运行会断。构建脚本须在打包前把软链接**解除为真实文件**。

### Phase 5 — 更新检查（手动更新）
- 主进程 `ipcMain.handle("check-update")` 请求：
  `https://api.github.com/repos/5044-xss/excavator/releases/latest`
- 比较 `tag_name`（如 `v1.0.0`）与 `app.getVersion()`。
- 触发时机：启动时静默检查一次 + 设置页「检查更新」按钮。
- 有新版：弹提示，「前往下载」用 `shell.openExternal` 打开 Release 页，**不自动下载 / 安装**。
- 未授权 GitHub API 60 次/时，足够。

### Phase 6 — electron-builder 打包
- ⚠️ **静态资源复制（易漏）**：`output:"standalone"` **不会**自动包含 `public/` 与 `.next/static`，而 `server.js` 以自身目录为根。构建脚本必须复制：
  - `public/` → `.next/standalone/public/`
  - `.next/static/` → `.next/standalone/.next/static/`
- ⚠️ **构建前清理 `.env`（防密钥泄露）**：Next 输出追踪会把 `.env*` 复制进 `.next/standalone`，卖家真实 API Key 会进安装包。打包脚本在 `next build` 前临时改名/移走 `.env`，构建后恢复。
- ⚠️ **`workspace/` 也会被追踪**：实测 `workspace/settings.json`（含卖家 API Key）与项目数据会被打进 standalone。已在 `next.config.ts` 用 `outputFileTracingExcludes` 排除 `workspace/keys/.env/resources/release`，构建脚本再加一道清理安全网双重保险。
- ⚠️ **Node 22 `fs.cpSync` 崩溃**：本机 Node 22.23.2 的 `fs.cpSync` 在 Windows 触发 `0xC0000409` 崩溃，复制静态资源必须手写递归 `copyDir`。
- ⚠️ **离线下载依赖代理**：`@electron/get`、electron-builder 下载走 Node 网络栈（不读系统代理），必要时设 `HTTPS_PROXY`；ffmpeg / Electron 二进制改用 `scripts/*.mjs` 调 `curl.exe`（读系统代理）。`electronDist` 指向本地 `node_modules/electron/dist` 免联网。
- `win.target: nsis`、`arch: x64`、`icon: build-resources/icon.ico`。
- ⚠️ **资源目录改名**：当前 `.gitignore:20` 有 `/build`，会忽略 electron-builder 资源。改用 `build-resources/`，并配置 `directories.buildResources: "build-resources"`。
- `oneClick: false`、`allowToChangeInstallationDirectory: true`、创建桌面 / 开始菜单快捷方式。
- `files` 含 `.next/standalone`、`electron`；`extraResources` 含 `resources/ffmpeg`；`asarUnpack` 原生模块（`**/node_modules/better-sqlite3/**`）。
- `productName: "掘漫"`，`appId: "com.5044.jueman"`。
- ⚠️ `artifactName` 用 ASCII：`Jueman-Setup-${version}.exe`（中文文件名在 NSIS 上偶发兼容问题），显示名仍为「掘漫」。
- 关闭生产环境 DevTools，精简菜单栏。
- 脚本：`npm run electron:dev`（开发）、`npm run dist`（先清理 .env → build → 复制静态资源 → rebuild ABI → electron-builder）。

### Phase 7 — 图标

## 五、风险与注意事项

- `better-sqlite3` 的 Electron ABI 重编译是头号坑，优先验证；且**顺序必须是先 build 后 rebuild**。
- 静态资源（`public` / `.next/static`）需手动复制进 standalone，否则界面 404。
- 构建前必须清理 `.env`，否则 Next 会把卖家密钥追踪进 standalone 包。
- 内置 ffmpeg + Electron + Next，安装包预计 **150–250MB**。
- 授权为离线签名，理论上可被逆向绕过；如需更强防护，后续再加壳 / 混淆。
- 数据目录迁移到 `userData` 后，开发环境与打包环境的数据不互通（正常现象）。
