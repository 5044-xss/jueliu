# 掘流 · 项目技术文档

> 本地单机 AI 漫剧创作工作台。流程：故事 → 剧本 → 资产 → 分镜 → 按厂商编排 → 第三方平台生成 → 回传视频 → 截帧/起始画面 → 合成导出。
> 文档面向开发者，描述架构、数据模型、核心流程与约定。

---

## 1. 项目概览

- **形态**：Next.js 全栈应用（App Router），可用 Electron 打包为 Windows 桌面程序。
- **运行模式**：本地单机、单用户；不依赖云端数据库，所有数据落在本机 `workspace/` 目录（打包后为 Electron `userData/workspace`）。
- **LLM**：通过 OpenAI 兼容接口调用（默认阿里百炼 DashScope），密钥在设置页填写；打包版不读宿主机环境变量。
- **媒体处理**：调用本机/内置 `ffmpeg` 做截帧与视频合成。
- **生成方式**：本工作台**不直接对接图像/视频生成**，而是把分镜编译成“可执行提示词 + 参考图上传清单”，由用户在第三方平台（豆包 Seedance、MiniMax H3 等）生成后回传。

### 技术栈

| 层 | 选型 |
| --- | --- |
| 框架 | Next.js 16（App Router，Turbopack）、React 19 |
| 语言 | TypeScript |
| 数据库 | better-sqlite3（每个项目一个 sqlite 文件） |
| UI | Tailwind CSS v4、shadcn 风格组件（`@base-ui/react`）、lucide-react、sonner |
| 校验 | zod |
| 桌面 | Electron 44、electron-builder |
| 媒体 | ffmpeg（系统 PATH 或打包内置） |

> ⚠️ 本项目使用的 Next.js 版本有破坏性变更：写代码前应先看 `node_modules/next/dist/docs/`，并遵守根目录 `AGENTS.md` 里的 Next 规则块。

## 2. 运行与构建

```bash
npm install
npm run dev            # 仅 Web，http://127.0.0.1:3000
npm run electron:dev   # 同时起 next dev + Electron
npm run typecheck      # tsc --noEmit
npm run lint           # eslint
npm run build          # next build（standalone 输出）
npm run dist           # 打包桌面版（scripts/build-desktop.mjs）
npm run ffmpeg:fetch   # 下载内置 ffmpeg
```

- **提交前必须**通过 `npm run typecheck` 与 `npm run lint`。
- 打包相关：`next.config.ts` 的 `output: "standalone"`、`serverExternalPackages: ["better-sqlite3"]`、`outputFileTracingExcludes['/*']`（严禁把 `workspace/**`、密钥、`.env` 追踪进包）。
- Electron 入口 `electron/main.cjs`：单实例锁、免费端口探测、spawn standalone server、激活/许可证（`activation.html`、`license.cjs`、`machine-id.cjs`）、退出时杀服务进程树。

## 4. 数据存储

### 4.1 workspace 布局

```
workspace/
  settings.json            # 全局设置（LLM/ffmpeg/autoGenerateAiPrompt）
  projects.json            # 剧集注册表（series + episodes 两级）
  library/                 # 全局资源库（可跨集复用）
    styles.json templates.json skills.json vendors.json
    asset-library-global.json  asset-library-<seriesId>.json
    asset-images/          # 资源库图片
  <projectId>/             # 每个“集”= 一个项目
    project.db             # sqlite（该集全部结构化数据）
    orchestration-cache.json  # 按厂商的编排缓存（见 §5.3）
    media/
      assets/  frames/  videos/  exports/
      frames|videos/<vendorId>/<segmentId>/...   # 媒体按厂商分区
    templates/ rules/
```

- 项目/系列 id 使用 UUID。**所有涉及 id 的路径拼接都经过 `paths.ts` 的 `isSafeId` 校验 + 工作区内约束**，防止路径穿越。
- 打开不存在的项目不再隐式创建（`getProjectDb` 要求目录+库存在；新建只由 `createEpisode` 触发）。

### 4.2 数据库主要表

| 表 | 作用 |
| --- | --- |
| `project` | 项目：名称/风格/style_id/画幅/默认段时长/vendor |
| `story` `script` `scene` | 故事文本、剧本、场次（含 `blocking_json` 站位） |
| `asset` `variant` `view` | 资产（角色/场景/道具）→ 变体 → 视角（含图片路径、original 快照用于还原） |
| `segment` | 段（按厂商派生的分组）：时长/模式/起始画面/video_path/status/ai_prompt 缓存 |
| `shot` `shot_ref` | 镜（持久主线，含 ideal_ms/original_json）；引用（角色/场景/道具） |
| `frame` | 帧图（kind: first/last/start） |
| `video_asset` `composition` | 回传视频、合成记录 |
| `job` | 生成任务状态（用于前端轮询） |

> 遗留表 `skill` / `prompt_template` / `continuity_rule_set` / `stale_mark` 目前未被运行时使用（连续性是代码内固定规则）。迁移以 `db/index.ts::migrate` 的 `addColumnIfMissing` + `MIGRATION_SIGNATURE` 控制，`meta.schema_version` 每次 migrate 同步。

## 5. 核心流程与机制

### 5.1 内容生产链

`故事(story)` →【技能 story-to-script】→ `剧本(script)` →【技能 script-to-assets】→ `资产(asset)` →【技能 script-to-storyboard】→ `镜(shot) + 站位(blocking)` →【编排 orchestration】→ `段(segment)` →【渲染 + AI 编译】→ 第三方提示词/上传清单 → 用户回传 `视频` → `截帧`（候选尾帧）→ 设为下一段起始画面 →【合成 compose】导出成片。

- 上游重生成会**失效级联**：换剧本 → 清空资产+分镜；换资产 → 清空分镜（并清理 `shot_ref` 悬空引用）。
- 生成类任务走 `job` 表：`startJob/finishJob`，前端 `useProjectJobs` 轮询；同名任务会把旧的 running 置为失败。

### 5.2 技能系统

- 代码注册表 `skills/registry.ts`：`story-to-script`、`script-to-assets`、`script-to-storyboard`、`storyboard-to-ai-prompt`。
- 可编辑技能提示词存资源库 `skills.json`，按 `kind` 维护多条、选“使用中”的一条；内置条目带 `builtinVersion`，未编辑过会随版本自动刷新，改过则标记 `edited` 不再覆盖；内置技能不可删除。
- 统一入口 `POST /api/skills/run`：按 `skillId` 分派，带 `inputSchema` 校验与 `job` 包裹；结构化输出经 `llm/structured.ts`（JSON Schema 契约 + 解析失败重试）。

### 5.3 厂商编排（orchestration）

- **厂商档案** `orchestration/vendors.ts`（内置豆包/H3，含能力参数与专属“翻译提示词” `compilePrompt`）→ 可编辑副本存 `library/vendors.json`（内置项带版本自动刷新、不可删除）。
- **打包算法** `orchestration/pack.ts::packScene`：纯函数，按 `maxShotsPerSegment / 时长上下限 / 参考图槽位 / 连续或硬切` 把一场的镜序列切成段。
- **落地** `orchestration/apply.ts::applyOrchestration`：以镜为主线，**非破坏式**重算分段、重分配 `shot.segment_id`；被打包变化影响的段清空视频/帧图/起始画面（并清 `video_asset`）。镜内容与 id 稳定。
- **按厂商缓存** `orchestration/cache.ts`：切厂商前把当前厂商的分段布局+视频+帧图+起始画面存进 `orchestration-cache.json`，切回时还原。缓存键 = `段内镜 id 序列` + `内容签名`（镜字段/引用/目标时长哈希），**镜被编辑过则不还原旧媒体**。
- **媒体按厂商分区**（`paths.ts`）：`frames|videos/<vendorId>/<segmentId>/...`，避免不同厂商复用同一 segment id 时相互覆盖。
- **并发**：`lock.ts::withLock` 使同一项目的编排串行；缓存文件临时文件+原子 rename。
- Orchestrate 接口：`POST /api/projects/[id]/orchestrate`，流程 `capture → apply → restore → updateProject.vendor`。

### 5.4 渲染与提示词

- `render.ts::renderSegment`：把段渲染成「正文 / 图例 / 参数」三段（模板来自 `templates.json`，平台化），并产出 `manifest`（图1..图N 的参考图上传清单，含起始画面）。
- `ai-prompt.ts`：AI 翻译提示词的**签名缓存**。签名覆盖 `正文+图例+参数+厂商编译提示词+模型`，任一变则失效。`storyboard-to-ai-prompt` 技能据此用厂商 `compilePrompt` 编译，并确定性补「首帧为图片N」锚定。
- 第三方生成弹窗 `components/generation-dialog.tsx`：展示起始画面（图1）、上传清单、AI 提示词与正文 tab；起始画面变化会自动重新生成一次 AI 提示词。

### 5.5 帧图与起始画面

- `frames.ts`：`first/last` 从本段视频截取；`start` 为外部上传/生成的“本段起始画面”。截帧成功后才解除别段采用；删除帧会同时解除采用并删文件。
- `keyframe.ts`：生成“单独起始画面”提示词；保存起始画面覆盖前先解除采用。
- 连续性：`render.ts` 用上一段尾帧做下一段首帧（`anchorToNext`），硬切则不需要。

### 5.6 合成

- `compose.ts`：按 `segmentIds` 顺序调用 ffmpeg 拼接（转场/时长），写入 `media/exports`，记录 `composition`。
- `ffmpeg.ts`：`runFfmpeg` 带超时与杀进程树（Windows 用 `taskkill /T /F`），stderr 截断；`detectFfmpeg` 探测可用性。

### 5.7 资源库

- 类型：`styles`（风格预设）、`templates`（平台提示词模板）、`skills`（技能提示词）、`vendors`（厂商档案）、`assets`（全局资产参考图，按 series 或 global 作用域）。
- 统一以 `library/store.ts` 读写 JSON：**原子写**（临时文件+rename）；解析失败会备份为 `*.corrupt-*.bak` 并返回默认值，避免损坏后静默覆盖。
- 内置项生命周期约定：`builtin` + `builtinVersion` + `edited`；未编辑的内置项按版本刷新，编辑过的不再覆盖，内置项不可删除。

## 6. 前端结构

- 顶部导航：首页 `/`、项目 `/projects`、资源库 `/library/*`、设置 `/settings`。
- 项目层级：`projects`（剧集列表）→ `projects/[seriesId]`（子集列表）→ `projects/[seriesId]/[episodeId]`（集内）。
- 集内 tab（`project-tabs.tsx` / 各 `page.tsx`）：故事 `story`、剧本 `script`、资产 `assets`、分镜 `storyboard`、合成 `compose`。
- 资源库 tab：风格 `styles`、厂商 `vendors`、技能 `skills`、资产 `assets`。
- 状态：客户端组件 + `fetch`；生成任务用 `useProjectJobs` 轮询 `/api/projects/[id]/jobs`。
- 弹窗统一用 `components/ui/dialog.tsx`；长内容弹窗采用“头部固定/中部滚动/底部按钮固定”的 flex 布局。

## 7. API 一览（按模块）

| 模块 | 主要接口 |
| --- | --- |
| 项目/剧集 | `GET/POST /api/projects`；`GET/PATCH/DELETE /api/projects/[id]`；`/api/projects/[id]/copy`；`/api/series/[id]`、`/api/series/[id]/episodes`、`/api/series/[id]/copy` |
| 故事/剧本/分镜 | `/api/projects/[id]/story`、`/script`、`/script/scenes/[sceneId]`、`/storyboard`、`/shots/[shotId]`、`/shots/[shotId]/restore` |
| 资产 | `/api/projects/[id]/assets`、`/assets/[assetId]`、`/assets/variants/...`、`/assets/views/.../image`、`/assets/restore`、`/assets/ensure-views` |
| 编排 | `POST /api/projects/[id]/orchestrate` |
| 段/镜 | `/api/projects/[id]/segments/[segmentId]`、`/segments/[segmentId]/repair`、`/restore` |
| 视频/帧 | `/segments/[segmentId]/video`、`/frames`、`/first-frame`、`/first-frame-image`、`/start-frame`；`/api/projects/[id]/frames/[frameId]`（PATCH/DELETE）、`/frames/[frameId]/image` |
| 提示词 | `/api/render/platform`、`/segments/[segmentId]/ai-prompt`、`/segments/[segmentId]/keyframe-prompt` |
| 合成 | `/api/projects/[id]/compositions`、`/compositions/[compositionId]`、`/compositions/[compositionId]/video` |
| 资源库 | `/api/library/styles|templates|skills|vendors|assets`（含 `[id]`） |
| 技能/任务 | `/api/skills/run`、`/api/projects/[id]/jobs` |
| 系统/设置 | `/api/settings`、`/api/settings/llm-test`、`/api/system/ffmpeg` |

**接口约定**：入参用 zod 校验；返回统一 `{ error }`；对不存在的项目/资源返回 404；写库可能抛错时包裹 try/catch。

## 8. 安全与健壮性约定（开发时请遵守）

1. **id 校验**：任何用 URL/请求体 id 拼路径前，先过 `isSafeId`；新项目目录必须在工作区内（`getProjectDir` 已加双重约束）；删除前确认是注册表登记过的真实项目。
2. **不隐式创建**：读取不存在的项目直接 404，不生成空目录/空库。
3. **原子写**：所有 JSON 存储用临时文件 + rename；解析失败先备份坏文件。
4. **媒体按厂商分区**，`first_frame_id` 等跨段引用在删除/覆盖前解除。
5. **编排串行**（`withLock`）+ 缓存内容签名，避免并发串数据与把旧媒体贴到改过的段上。
6. **错误处理**：前端所有 `fetch` 都要判 `res.ok` 并 try/catch/finally，避免“假成功”和按钮卡死；异步更新组件前检查是否已卸载。
7. **删除操作**：内置资源不可删；删除资源时同步清理引用（如 `shot_ref`）。

## 9. 常见开发任务

- **加一个厂商**：在资源库“厂商”页新增，或改 `orchestration/vendors.ts` 的 `DEFAULT_VENDORS`（记得同步 `library/templates` 的平台模板）。
- **改内置提示词/模板**：改 `lib/skills/prompts.ts` 或 `lib/templates-defaults.ts`，并递增对应的 `BUILTIN_*_VERSION`，未编辑过的内置项会自动刷新。
- **改段打包规则**：`orchestration/pack.ts`（纯函数，易单测）；改厂商默认能力时递增 `library/vendors.ts` 的 `BUILTIN_VENDOR_VERSION`。
- **改数据库结构**：在 `db/schema.ts` 的 `SCHEMA_SQL` 加列/表，并在 `db/index.ts::migrate` 用 `addColumnIfMissing`，最后递增 `MIGRATION_SIGNATURE`。
