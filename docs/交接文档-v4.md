## 1. 项目定位与能力边界

本地单人 AI 漫剧创作工作台（不部署服务器）。目标：把「一致性」和「连续性」在**提示词/约束/数据结构**层做到极致。

```
项目 → 故事 → 剧本 → 资产 → 分镜(段/镜) → 平台提示词 → 外部生成 → 回传视频 → 截尾帧 → 合成(M7未做)
```

**能力边界（必须接受）**：本工作台只保证「提示词/约束/数据结构正确」，**不保证第三方模型生成的画面**。站位等字段是模型自填，不是像素级验证。

**非目标**：不做视频/图片生成、不做云端部署、不做模型训练。

## 5. 提示词体系与资产模型

- 内置提示词唯一来源：`src/lib/skills/prompts.ts`，`BUILTIN_SKILL_VERSION = 15`。
- 三个技能：`story-to-script` / `script-to-assets` / `script-to-storyboard`（技能库里是真实条目，`builtin`+`builtinVersion`，可选用/复制自定义）。
- 单段 AI 修复提示词：`STORYBOARD_REPAIR_PROMPT`（同文件，代码内，不进军技能库）。
- 输出 JSON 结构由 `lib/llm/structured.ts` 的契约强制，**不要写回提示词**。
- 技能库 = 每类多个条目 + 「使用中」单选（`isDefault`）；`getActiveSkillPrompt(kind)` 只读选中条目的 prompt，无隐藏兜底；改 `prompts.ts` 后递增版本号，内置条目会自动刷新（自定义条目不受影响）。

### 5.1 资产模型（v3 已定，供确认）
| 类型 | 结构 | 参考图 | 备注 |
|---|---|---|---|
| 角色 | 资产 = **锚点（不变项）**；变体 = **造型** | 每个造型 **1 张「四视图」** | 基础造型（如「日常装」）+ 变装；同场同角色只用同一造型 |
| 场景 | 资产 = **场景锚点**；变体 = 时间/天气 | 每个变体 **1 张「全景」** | 纯空镜、无人物；按地点建资产，name 照抄 `location` 原文 |
| 道具 | 资产 = **道具锚点**；1 个变体 | 1 张「正面」 | 拆分粒度是当前最大争议，见 14.1 |

`defaultViewLabels(type)`（`src/lib/assets.ts:47`）：角色 `["四视图"]`、场景 `["全景"]`、道具 `["正面"]`。变体没视角时按类型补默认视角。

### 5.2 提示词要点
- **故事→剧本**：目标/冲突/结果、情绪翻转、因果衔接、场尾钩子、动机/称谓锁定、台词（≤25 字/潜台词/无冗余）。
- **剧本→资产**：角色只写锚点（不含服装），造型只写变化项；每个变体 1 个「四视图」且 view.prompt 是完整四视图提示词；变体名与视角名不得同名；场景纯空镜、每个变体一张 16:9 全景、name 用 location 原文、每个地点都要有资产；道具只提关键/反复出现的；参考图比例：角色 1:1 横排、场景 16:9 或 1:1、道具 1:1，**不要用视频的 9:16**。
- **剧本→分镜**：段 ≤3 镜；targetMs 按内容估算（台词约 4~5 字/秒），上限=项目默认段时长、下限 3000ms，最后一段按剩余内容；**内容全覆盖**（每句台词/动作必落分镜，装不下就拆段）；景别递进/情绪近景/不越轴；镜间衔接；跨段首帧锚定（硬切/场次首段除外）；refs 标签精确匹配；**同场同角色只用同一变体**；blocking 覆盖本场全部出场角色（含闯入者）；`camera.side` + `subjectNodeIds`。

## 8. 核心设计决策

1. **输出结构由内置契约强制**（`lib/llm/structured.ts`），重试 + 关闭 json_mode 回退。
2. **技能库 = 每类多个条目 + 选用**，内置是真实条目；改 `prompts.ts` 必须递增版本号。
3. **图片清单编号**：`首帧 → 场景 → 角色 → 道具`；同一 `viewId` 复用同一编号；提示词用 `@图N`（`lib/render.ts` `buildManifest`）。
4. **首帧锚定**：段尾帧设为下一段首帧；**不跨场**；`hardCut` 段跳过；渲染按「连续/硬切」给情境化首帧提示。
5. **段时长内容驱动**：targetMs 按内容估算，不再一律 10s；分镜页可手动微调。
6. **段内最多 3 镜**；段间靠首帧锚定；跨段可锁的只有「上段尾帧 = 本段首帧」。
7. **角色变体模型**：资产 = 基础参考图（第一个变体），变体 = 延伸造型。
8. **站位/轴线**：场级 blocking（轴线/镜头侧/节点坐标朝向）**整段注入**每段提示词；分镜记录 `camera.side` + `subjectNodeIds` 并校验。
9. **引用解析加固**：`resolveRefLabels` 精确匹配；**只有一个候选时回退使用它**（避免单一变体/视角因标签出入失败）；找不到就置空交给校验器报警，不静默替换。
10. **连续性规则内部固定全开**（`CONTINUITY_RULES`，`lib/storyboard.ts:498`），页面上不暴露开关；`getContinuityRules()` 不再读库。
11. **M8 失效级联（最小版）**：见第 9 节。

## 10. 连续性与校验器（`lib/continuity.ts`）

输出 warning/info，不阻塞；warning 按「场次+段+消息」去重。已覆盖：

- 段内镜数 ≤3、分镜时长之和↔targetMs（偏差 >10%）、targetMs 超上限/低于下限、内容少但接近上限（可能硬撑）
- 跨段首帧锚定缺失（硬切/场次首段跳过）
- 焦段跳变（info）
- 场次地点无对应场景资产（宽松匹配）
- 场景引用↔本场 location（宽松匹配）、场景变体↔timeOfDay（日/夜）
- 出场角色是否有角色资产（画外音/电话/旁白等跳过）
- **台词覆盖**：剧本每句台词必须出现在分镜（去括号提示/标点后比对）
- **同场同角色变体一致性**（忽蓝忽红）
- **引用未匹配视角 / 引用悬空**（指向已删除视角 → "参考图引用已失效，请重新生成分镜"）
- **站位**：`camera.side`↔场级 cameraSide（越轴）、`subjectNodeIds` 是否存在、镜中角色是否在 blocking.nodes
- 有动作但未引用角色参考图（info）

宽松匹配：去标点后包含关系 + 共享 ≥3 个连续汉字（LCS）+ 按 `/` 拆多地点。

## 11. AI 修复（单段，`api/projects/[id]/segments/[segmentId]/repair/route.ts`）

1. 取本段 warning + 本段分镜 + 前后段摘要 + 本场剧本 + 资产清单 + blocking，交大模型重写本段分镜。
2. **在事务里应用并跑全项目校验**：本段 warning 未清零、或**其他段冒出新 warning** → **回滚**重试。
3. 最多 2 次（`MAX_ATTEMPTS`）；仍失败则保留原分镜并返回 422。
4. 不覆盖 `shot.original_json`，所以「复原」仍可回退到最初生成的内容。

## 12. 一致性能力评估（诚实版）

**能覆盖（提示词/约束/数据层）**：
- 人物一致性：锚点 + 造型四视图作参考图；每镜强制 character 引用；渲染注入「保持脸型/发型/服装一致」；同场变体不串色校验。
- 场景一致性：一张干净全景作参考图；场景引用↔地点/时间校验；blocking 空间锚点注入。
- 站位/机位：场级 blocking 整段注入；`cameraSide`/`subjectNodeIds` 校验越轴与节点存在；blocking 覆盖出场角色。
- 镜头连续性：段内镜间衔接规则；段间首帧锚定 + 硬切标记；批量锚定。
- 故事不穿帮：台词/动作全覆盖 + 覆盖校验；M8 级联避免上下游错配；引用解析加固 + 悬空检测。
- 可维护性：任务状态、快照复原、逐镜/站位/资产可编辑。

**不能保证**：第三方模型是否听话、画面是否崩坏；站位字段是模型自填（准确率约 8~9 成），非像素级验证；段内多镜切换由平台执行，时长是引导值。

## 14. 待澄清 / 讨论问题

### 14.1 道具拆分粒度（用户明确不满）
现状：实测项目 `我是苏皖` 拆出 6 个道具（中奖彩票、设计草图、白玫瑰、苏打水、现金、名片）。
用户观点：现金/苏打水/名片这类**只出现一次**的东西不该单独建资产、不该占参考图槽位，只在动作描述里写一次即可。
需澄清：判定规则（出现次数 ≥2？剧情关键？跨镜外观一致？）、一次性道具是否一律不建资产、是否设硬上限。
建议：只给「跨镜复用、且外观必须一致」的道具建资产，一次性道具写进动作描述。

### 14.2 参考图槽位预算（硬约束）
每段清单 = 首帧(0/1) + 场景(1) + 角色(每出场 1) + 道具(每引用 1)。例：酒吧戏 首帧1+场景1+角色3+道具2 = 7 张。
需澄清：目标平台**最多能传几张**？超限优先级怎么砍（建议 首帧 > 场景 > 角色 > 道具）。

### 14.3 场景参考图形态
已定：一张干净 16:9 全景。待确认：是否够支撑场景一致性 + 站位？是否需要一个**不上传、只给人看**的站位示意图？

### 14.4 造型与场次的对应
角色可有多个造型，分镜按场次选造型。待确认：**谁决定这场穿哪套**？是否在资产页给造型标注适用场次？

### 14.5 内容覆盖
漏台词/动作是接受「AI 修复」流程，还是要求生成时更严格（缺一条就整段重生成）？

### 14.6 是否暴露规则/参数
连续性规则已定内部全开、不暴露。是否还有其它内部参数（段时长、每段镜数上限、参考图上限）需暴露或写死？
