## 1. 项目定位与能力边界

本地单人 AI 漫剧创作工作台（不部署服务器）。目标：把「一致性」和「连续性」在**提示词/约束/数据结构**层做到极致。

```
项目 → 故事 → 剧本 → 资产 → 分镜(段/镜) → 平台提示词 → 外部生成 → 回传视频 → 截尾帧 → 合成
```

**能力边界（必须接受）**：本工作台只保证"提示词/约束/数据结构正确"，**不保证第三方模型生成的画面**。站位等字段是模型自填，不是像素级验证。

**非目标**：不做视频/图片生成、不做云端部署、不做模型训练。

## 5. 提示词体系

- 内置提示词唯一来源：`src/lib/skills/prompts.ts`，`BUILTIN_SKILL_VERSION = 11`。
- 三个技能：`story-to-script` / `script-to-assets` / `script-to-storyboard`（技能库里是真实条目，`builtin`+`builtinVersion`，可选用/复制自定义）。
- 单段 AI 修复提示词：`STORYBOARD_REPAIR_PROMPT`（代码内，不进军技能库）。
- 输出 JSON 结构由 `lib/llm/structured.ts` 的契约强制，**不要写回提示词**。

### 5.1 本轮提示词要点
- **故事→剧本**：目标/冲突/结果、情绪翻转、因果、场尾钩子、称谓锁定。
- **剧本→资产**：外观锚点；**角色默认变体「日常装」，视角固定「四视图」；变体名与视角名不得同名**；**场景纯空镜、无人物**，views 至少 **全景 + 俯瞰图（俯视平面布局）**，按需加反打/左/右；**参考图比例：角色四视图 1:1 横排、场景 16:9 或 1:1、道具 1:1，不要用视频的 9:16**；每个变体必须至少 1 个视角。
- **剧本→分镜**：段≤3 镜；**targetMs 按内容估算**（台词约 4~5 字/秒），上限=项目默认段时长、下限 3000ms，最后一段按剩余内容、不硬撑；**内容全覆盖（每句台词/动作必落分镜，装不下就拆段）**；景别递进/情绪近景/不越轴；镜间衔接；跨段首帧锚定（硬切/场次首段除外）；refs 标签精确匹配；**同场同角色只用同一变体**；blocking 覆盖本场全部出场角色（含闯入者）；camera.side + subjectNodeIds。

## 7. 核心设计决策

1. **输出结构由内置契约强制**（`lib/llm/structured.ts`），重试+回退。
2. **技能库=每类多个条目+选用**，内置是真实条目；改 `prompts.ts` 必须递增版本号。
3. **图片清单编号**：首帧 → 场景 → 角色 → 道具；同 viewId 复用编号；提示词用 `@图N`。
4. **首帧锚定**：段尾帧设为下一段首帧；**不跨场**；`hardCut` 段跳过锚定；渲染的"首帧提示"按"连续/硬切"给情境化文案。
5. **段时长内容驱动**：targetMs 按内容估算，不再一律 10s；可在分镜页手动微调。
6. **段内最多 3 镜**；段间靠首帧锚定；跨段可锁的只有"上段尾帧=本段首帧"。
7. **角色变体模型**：资产=基础参考图（第一个变体），变体=延伸造型；角色每个变体一张「四视图」；场景每个变体至少「全景+俯瞰图」。
8. **站位/轴线**：场级 blocking（轴线/镜头侧/节点坐标朝向）**整段注入**到每段提示词；分镜记录 `camera.side`+`subjectNodeIds` 并校验。
9. **引用解析加固**：`resolveRefLabels` 精确匹配，但**只有一个候选时回退使用它**（避免角色单一变体/单一视角因标签出入而失败）。
10. **M8 失效级联（最小版）**：见第 8 节。

## 8. 失效级联（M8 最小版）

依赖图：`故事 → 剧本 → 资产 → 分镜 → 视频/合成`

**已实现的清空规则**（服务端强制，客户端二次确认）：
| 触发 | 清空的下游 |
|---|---|
| 重新生成剧本（story-to-script） | 资产、分镜 |
| 清空剧本（DELETE script） | 资产、分镜 |
| 重新生成资产（script-to-assets / PUT assets） | 分镜 |
| 清空资产（DELETE assets） | 分镜 |
| 重新生成分镜（script-to-storyboard） | 分镜重建（段/镜/帧/视频行随段级联删除） |

实现位置：`api/skills/run/route.ts`、`api/projects/[id]/{script,assets}/route.ts`；工具函数 `clearAssets()`、`clearStoryboard()`。
确认文案已更新（如"重新生成将覆盖当前剧本，并清空下游的「资产」和「分镜」"）。

**未做**：改**故事文本**不会自动失效下游（故事页是显式保存，未级联）；`stale_mark` 表未启用；视频/合成级联未做（M7 未做）。

## 9. 连续性与校验器（`lib/continuity.ts`）

输出 warning/info，不阻塞。已覆盖：
- 段内镜数 ≤3、时长之和↔targetMs、**targetMs 超上限/低于下限、内容少但接近上限（可能硬撑）**
- 跨段首帧锚定缺失（硬切/场次首段跳过）
- 焦段跳变（info）
- 场景引用↔本场 location（**宽松匹配**：去标点后允许包含关系）、场景变体↔timeOfDay
- 出场角色是否有角色资产
- **台词覆盖**：剧本每句台词必须出现在分镜（去括号提示/标点后比对）
- **同场同角色变体一致性**（忽蓝忽红）
- **引用未匹配视角 / 引用悬空**（指向已删除的视角 → "参考图引用已失效，请重新生成分镜"）
- **站位**：`camera.side`↔场级 cameraSide（越轴）、`subjectNodeIds` 是否存在、镜中角色是否在 blocking.nodes

## 10. AI 修复（单段）

`POST /api/projects/[id]/segments/[segmentId]/repair`：
1. 取本段 warning + 本段分镜 + 前后段摘要 + 本场剧本 + 资产清单 + blocking，交大模型重写本段分镜；
2. **在事务里应用并跑全项目校验**：本段 warning 未清零、或**其他段冒出新 warning** → **回滚**重试；
3. 最多 2 次；仍失败则保留原分镜并报错。
4. 结果不覆盖 `original_json`，所以"复原"仍可回退到最初生成的内容。

## 11. 一致性能力评估（诚实版）

**能覆盖（提示词/约束/数据层）**：
- **人物一致性**：基础四视图+变体四视图作参考图；每镜强制 character 引用；渲染注入"保持脸型/发型/服装一致"；同场变体不串色校验。
- **场景一致性**：场景资产（全景+俯瞰图+反打）作参考图；场景引用↔地点/时间校验；blocking 空间锚点注入。
- **站位/机位**：场级 blocking 整段注入；分镜 cameraSide/subjectNodeIds 校验越轴与节点存在；blocking 覆盖出场角色。
- **镜头连续性**：段内镜间衔接规则；段间首帧锚定 + 硬切标记；批量锚定。
- **故事不穿帮**：台词/动作全覆盖 + 覆盖校验；M8 级联避免上下游错配；引用解析加固 + 悬空检测。
- **可维护性**：任务状态、快照复原、逐镜/站位/资产可编辑。

**不能保证**：
- 第三方模型是否听话、画面是否崩坏（能力边界）；
- 站位字段是模型自填，准确率约 8~9 成，不是像素级验证；
- 段内多镜切换由平台执行；时长是引导值。

**结论**：在"提示词/约束/数据结构"层已接近上限，能显著降低穿帮概率并把问题**暴露出来可修复**；最终画面仍取决于模型。
