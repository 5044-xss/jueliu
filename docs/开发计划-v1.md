# AI 漫剧工作台 · 开发计划 v1.1

> 文档状态：v1.1 草案
> 定位：本地运行的单人创作工作台（不部署服务器）
> v1.1 变更：确定 LLM 供应商（阿里百炼）、Scene→Segment 1:N、默认 multi-shot；2D 站位图 v1 不做

---

## 0. 首要目标与能力边界（最重要，先读这一节）

### 0.1 首要目标

**本工作台产出的提示词，拿去第三方平台生成的视频必须做到：**

1. **人物一致性**：同一角色跨分镜、跨段落脸型/发型/服装/体型稳定，不崩不换。
2. **场景一致性**：同一场景跨分镜、跨段落空间、光线、色调稳定。
3. **机位/站位一致**：人物站位不错乱，镜头不跳轴、不穿帮。
4. **衔接丝滑**：镜与镜之间动作连续、视线匹配、光线连续；段与段之间首尾帧锚定。
5. **最终视频丝滑**：无站位错乱、无镜头穿帮、无角色突变。

一句话：**把"一致性"和"连续性"在提示词层面做到极致。**

### 0.2 能力边界（必须接受，否则验收无法成立）

| 层 | 谁负责 | 说明 |
|---|---|---|
| 提示词 / 约束 / 数据结构 | **本工作台（我们）** | 保证提示词正确、约束完备、参考图与编号一致 |
| 画面像素级结果 | **第三方模型（豆包/即梦等）** | 模型是否听话、是否崩坏，我们无法控制 |

**结论**：本工作台保证"提示词 ok"，不保证"模型一定生成完美画面"。任何只做提示词的工具都无法保证后者。

### 0.3 非目标（明确不做）

- ❌ 不做视频生成
- ❌ 不做图片/资产生成
- ❌ 不做云端部署 / 多人协作
- ❌ 不做模型训练或微调

## 1. 项目概述

### 1.1 工作流

```
项目 → 故事 → 剧本 → 资产 → 分镜(段/镜) → 平台提示词 → 外部生成 → 回传视频 → 截尾帧 → 合成
```

### 1.2 各环节职责

| 环节 | 输入 | 输出 | 说明 |
|---|---|---|---|
| 故事 | 用户想法 | 故事文本 | 纯文本 |
| 剧本 | 故事 | 结构化剧本（场次/对白/动作） | Skill 生成 |
| 资产 | 剧本 | 角色四视图/变体、场景、道具 | Skill 出提示词，外部生成图后回传 |
| 分镜 | 剧本 + 资产 | 段落 + 分镜（含时长/机位/参考图引用） | Skill 生成，受连续性规则约束 |
| 平台提示词 | 段 + 模板 | 豆包/即梦等可复制提示词 + 图片清单 | 模板渲染 |
| 外部生成 | 提示词 + 图片 | 视频 | 用户在第三方平台完成 |
| 回传 | 视频 | 视频资产 | 上传到工作台 |
| 截尾帧 | 视频 | 尾帧图 | 本地 ffmpeg，人工确认 |
| 合成 | 多段视频 | 成片 | 本地 ffmpeg，拼接 + 转场 |

## 2. 核心概念与术语

| 术语 | 定义 |
|---|---|
| 项目 Project | 一次创作的整体，含风格、比例、默认段时长 |
| 故事 Story | 原始故事文本 |
| 剧本 Script | 结构化剧本，含场次、对白、动作 |
| 场次 Scene | 剧本的语义单位，也是**连续性上下文容器**（同场 = 同站位/光线/服装） |
| 资产 Asset | 可复用实体：角色 / 场景 / 道具 |
| 变体 Variant | 资产的一种形态（角色造型/状态、场景光照或角度） |
| 视角 View | 变体下的一张参考图（角色：一张四视图合成图；场景：全景/左/右/反打） |
| 段 Segment | **一次视频生成单位**，含 N 个分镜，对应一张视频卡片 |
| 分镜 Shot | 段内的镜头单元，有时长、机位、动作、台词、参考图引用 |
| 引用 Ref | 分镜对"资产+变体+视角"的引用 |
| 图片清单 Manifest | 段内参考图的有序编号列表（图1…图N） |
| 首帧锚定 Anchor | 上段尾帧作为本段首帧，保证跨段连续 |
| 平台模板 Template | 把段数据渲染成某平台提示词的模板 |
| Skill | 生成某类产物的能力单元 = 提示词模板 + 结构化输出 schema |
| 连续性规则集 | 项目级规则文件，约束轴线/视线/光线/焦段/服装道具等 |
| Blocking | 场次的空间关系：人物位置/朝向、机位位置/朝向、180°轴线 |

## 3. 数据模型

### 3.1 实体关系

```
Project
 ├─ Story
 ├─ Script ── Scene[]              # Scene → Segment 为 1:N
 ├─ Asset[] ── Variant[] ── View[]
 ├─ Segment[] ── Shot[] ── Ref[]   # Segment.sceneId 指向所属场次
 ├─ VideoAsset[] / Frame[]
 ├─ PromptTemplate[]
 ├─ Skill[]
 ├─ ContinuityRuleSet
 └─ Composition
```

**Scene 与 Segment 的关系（1:N）**
- **Scene 是连续性上下文容器**：同一场次共享站位、光线、服装、轴线等连续性约束。
- **Segment 是生成单位**：按生成目标切分。切分触发条件：超过最大时长 / 主体或机位组变化 / 对白过多。
- 例：1-1 场（城市广场）拆为 2 段 —— 段1 大屏亮相、段2 三人反应。

### 3.2 关键结构（示意）

```ts
Project {
  id, name,
  style,              // 风格，如"写实国漫"
  aspectRatio,        // 9:16 / 16:9 / 1:1
  defaultSegmentMs,   // 默认段时长
  createdAt, updatedAt
}

Scene {
  id, projectId, scriptId, index,
  slug,               // 第1-1场
  location, timeOfDay, interiorExterior,
  blocking: Blocking, // 本场空间关系（见 7.1）
  // segments 通过 Segment.sceneId 反向关联（1:N）
}

Asset {
  id, projectId,
  type: 'character' | 'scene' | 'prop',
  name,
  basePrompt,
  variants: Variant[]
}

Variant {
  id, assetId,
  label,              // 日常装 / 受伤装 / 白天 / 夜晚
  views: View[]
}

View {
  id, variantId,
  label,              // 角色：四视图；场景：全景 / 左 / 右 / 反打
  imagePath,          // 本地文件路径
  prompt
}
// 角色变体默认产出 1 张「四视图」合成图（正/侧/背/45° 在同一张内）
// 场景变体可挂多张角度图

Segment {
  id, projectId, sceneId, index,
  generationMode,     // 'multi-shot'（默认）| 'per-shot'（退化）
  firstFrameId?,      // 首帧（来自上段尾帧或手动上传）；若有则默认占图片清单图1
  shots: Shot[],
  status: 'draft' | 'generated' | 'returned' | 'composed',
  videoPath?          // 回传视频
}
// 约束：段内各分镜 durationMs 之和 = 该段目标时长（如 10000ms）
// v1 平台默认：每段最多 3 个分镜；时长为引导值，平台可能不精确执行

Shot {
  id, segmentId, index,
  durationMs,
  camera: { focal, shotSize, angle, movement },
  lighting,
  action, dialogue, expression,
  refs: Ref[]
}

Ref {
  role: 'first_frame' | 'character' | 'scene' | 'prop',
  assetId, variantId, viewId
}

// 段级图片清单，渲染时自动生成
ManifestItem {
  slot: number,        // 图1, 图2 ...
  role, label,         // 图2=沈清和(日常装·正面)
  imagePath
}
```

### 3.3 图片清单编号规则（防错核心）

1. 顺序固定：`首帧(若有) → 场景 → 角色(按出场顺序) → 道具`
2. 同一张参考图在段内**复用同一个编号**
3. 不同角度 / 不同变体 = 不同编号
4. **弹窗展示顺序 = 图N 顺序 = 用户上传顺序**（硬约束）

## 5. Skill 库设计

### 5.1 结构

每个 Skill 是一个可扩展单元：

```ts
Skill {
  id, name, description, version,
  inputSchema,          // zod
  outputSchema,         // zod，强制结构化输出
  promptTemplate,       // 变量占位
  modelParams,          // temperature 等
  enabled
}
```

### 5.2 内置 Skill

| Skill | 输入 | 输出 |
|---|---|---|
| `story-to-script` | 故事 + 项目设定 | 结构化剧本（场次/对白/动作） |
| `script-to-assets` | 剧本 | 角色/场景/道具 + 四视图提示词 + 变体建议 |
| `script-to-storyboard` | 剧本 + 资产 + 连续性规则 | 段[] + 分镜[] + 参考图引用 + blocking |

### 5.3 内置 Skill 输出 Schema（示意）

所有输出经 zod 校验；字段名可微调，结构固定。

**`story-to-script` → Script**
```ts
Script {
  title: string,
  scenes: [{
    index: string,          // "1-1"
    slug: string,           // 第1-1场
    location: string,       // 城市广场
    timeOfDay: string,      // 日
    interiorExterior: '内' | '外',
    summary: string,
    characters: string[],   // 出场角色名
    beats: [{
      type: 'action' | 'dialogue',
      character?: string,
      text: string
    }]
  }]
}
```

**`script-to-assets` → AssetDraft[]**
```ts
AssetDraft {
  type: 'character' | 'scene' | 'prop',
  name: string,
  basePrompt: string,        // 含项目风格关键词
  variants: [{
    label: string,           // 生日盛典造型 / 白天
    prompt: string,          // 该变体生成提示词
    views: [{ label, prompt }] // 角色：四视图；场景：全景/反打…
  }]
}
```

**`script-to-storyboard` → StoryboardDraft**
```ts
StoryboardDraft {
  scenes: [{
    sceneIndex: string,
    blocking: Blocking,      // 见 7.1
    segments: [{
      index: number,
      generationMode: 'multi-shot' | 'per-shot',
      targetMs: number,      // 段目标时长
      shots: [{
        durationMs: number,  // 各镜之和 = targetMs
        camera: { focal, shotSize, angle, movement },
        lighting: string,
        action: string,
        dialogue?: string,
        expression: string,
        refs: [{ role, assetName, variantLabel, viewLabel }]
      }]
    }]
  }]
}
```
> refs 用名称引用资产，落库时解析为 assetId / variantId / viewId。

### 5.4 拓展方式

- 新增 Skill = 新增一份配置（模板 + schema），无需改核心代码
- Skill 可版本化，历史产物记录所用版本
- LLM 输出强制走 schema 校验，失败自动重试并回退

## 6. 平台适配模板

### 6.1 模板组成（三部分缺一不可）

1. **正文模板**：结构化段数据 → 平台可读提示词正文
2. **参数模板**：比例 / 每镜时长 / 首帧槽位 / 是否首帧生视频 → 设置清单
3. **图例模板**：`图1=首帧，图2=沈清和(日常装·正面)…` 自动生成

### 6.2 模板对象

```ts
PromptTemplate {
  id, platform: 'doubao' | 'jimeng' | 'custom',
  name, version,
  bodyTemplate, paramsTemplate, legendTemplate,
  variables: string[],   // 可用变量清单
  editable: true         // 用户可编辑
}
```

### 6.3 渲染管线

```
段数据
 → 注入项目风格关键词
 → 构建 Manifest（去重/排序/编号）
 → 注入 @图N
 → 渲染正文
 → 渲染图例
 → 渲染参数清单
 → 输出 { body, legend, params, manifest }
```

### 6.4 默认正文骨架（通用）

```
【基础设定】风格 / 比例 / 场景(参考图N)
【角色一致性】图例 + 每个角色的"不变项"
【空间与站位】相对位置 + 180°轴线 + 首帧接续
【分镜序列】每镜：时长/景别/焦段/机位/光线/动作/台词，按机位选角度参考图
【衔接约束】镜间动作衔接 / 视线匹配 / 光线连续 / 焦段逻辑
【负面约束】换脸/换装/跳轴/多手多脚/畸变/水印/场景突变…
```

> 该骨架是**通用**的，不绑定任何平台；豆包/即梦模板都在它之上做平台化适配。

### 6.5 说明

- 平台无官方提示词规范，"适配"为经验模板，**必须用户可编辑**
- 参数只做**展示与勾选引导**，不假装能自动填平台
- 新平台 = 新增模板，不改核心

### 6.6 v1 平台默认行为与模板策略

- **提示词模板**：v1 只提供**通用默认模板**；豆包/即梦等平台专属模板**留好口子**（`platform` 字段 + 可插拔模板），后续补充，不做硬编码。
- **生成弹窗**：Tab（豆包/即梦/…）保留，初期各 Tab 都用默认模板渲染，平台专属内容后续替换。
- **默认生成行为**（先按此走，后续实测再调）：
  - 生成模式：**multi-shot**，每段**最多 3 个分镜**
  - 时长：**不固定**，`durationMs` 仅作引导
  - 图片槽位：提示词统一用 **`@图N`** 引用，弹窗按序展示、按序上传
  - 首尾帧：**支持**，默认走首尾帧锚定

## 7. 连续性与 Blocking（"丝滑"的核心抓手）

### 7.1 Blocking 数据结构

场次级空间关系，供分镜 Skill 遵守、校验器检查、俯视图渲染：

```ts
Blocking {
  axis: { from: NodeId, to: NodeId },        // 180° 轴线（两个锚点）
  cameraSide: 'left' | 'right',              // 镜头恒定处于轴线哪一侧
  nodes: [
    { id, label, type: 'character'|'prop'|'screen'|'landmark',
      pos: { x, y },                          // 俯视相对坐标 0~1
      facing: number }                        // 朝向角度
  ],
  paths: [ { nodeId, points: [{x,y}] } ]      // 运动轨迹
}
```

### 7.2 连续性规则集

项目级规则文件，分镜 Skill 强制满足，并提供校验器。

```json
{
  "axis180": true,          // 不跨轴线，保持镜头同侧
  "eyelineMatch": true,     // 视线匹配
  "lightingContinuity": true,
  "focalLogic": true,       // 焦段变化有逻辑，禁止无理由跳变
  "wardrobeProp": true,     // 服装/道具连续
  "blockingLock": true,     // 站位锁定
  "actionMatch": true,      // 动作衔接不跳帧
  "firstFrameAnchor": true  // 跨段首尾帧接续
}
```

**校验时机**：分镜生成后、提示词渲染前，输出警告（如"镜2→镜3 可能跳轴"）。

### 7.3 2D 站位图

- **v1 不做**：仅保留结构化文本 blocking（`Blocking` 数据 → 文字描述渲染进提示词），不渲染俯视图。
- **v2 再评估**：可视化为只读 SVG，或做可拖拽编辑器（拖完回写 `Blocking`）。

## 8. 视频回传 / 截尾帧 / 首帧锚定

1. 段卡片点击"第三方生成" → 弹窗（平台 Tab）
2. Tab 内容：提示词正文 + 参数清单 + 图片清单（按序缩略图）
3. 用户复制 → 到平台粘贴、按序上传图片 → 生成
4. 生成视频回传到工作台（上传本地）
5. ffmpeg 提取尾帧 → **人工确认**
6. 尾帧写入下一段 `firstFrameId`，成为其图片清单的图1
7. 段状态流转：`draft → generated → returned`

> **v1 默认**：弹窗 Tab 用通用默认模板渲染；支持首尾帧；图片用 `@图N` 引用、按序上传。平台实测细节后续再调。

---

## 9. 合成

- 选择参与合成的段并排序
- **归一化**：拼接前统一分辨率、帧率、像素格式（不同平台/不同次生成的视频参数可能不一致）
- ffmpeg：拼接（concat）+ 转场（xfade，可选）
- 导出到 `exports/`
- 范围：仅拼接与转场（不含 TTS/字幕/BGM）
- **v1 明确接受"无配音半成品"**：成片无配音、无字幕；配音/字幕留待后续版本评估

---

## 10. 失效级联

- 依赖图：Story → Script → Assets → Storyboard → (视频/合成)
- 上游任何编辑 → 下游全部标记 stale → **二次确认弹窗** → 清空下游
- 不做自动静默重生成（可控、省成本）

## 11. 页面规划

| 页面 | 内容 |
|---|---|
| 项目列表 | 新建（风格/比例/默认段时长）、打开、删除 |

| 工作台 · 剧本 | 结构化剧本查看/编辑，触发生成 |
| 工作台 · 资产 | 角色(四视图+变体) / 场景(角度) / 道具；提示词复制、图片回传 |
| 工作台 · 分镜 | 段卡片列表、分镜编辑、参考图选择器、连续性校验提示 |

## 14. 风险与开放问题

| # | 风险/问题 | 影响 | 应对 |
|---|---|---|---|
| 1 | 平台多分镜/时长/`@`引用/首尾帧的实际行为未验证 | 段质量 | v1 按默认走（multi-shot ≤3 镜、`@图N`、支持首尾帧）；保留 `per-shot` 退化；后续实测再调 |

| 6 | 阿里百炼模型/接口差异 | 接入 | OpenAI 兼容层 + 页面可配置，随时换模型 |

## 15. 已确认 / 待确认

**已确认**
1. LLM：阿里百炼，OpenAI 兼容，页面可配置（key 已在 env）
2. 场次↔段：Scene → Segment 为 **1:N**，Scene 为连续性上下文容器
3. 多分镜：默认 **multi-shot**，每段最多 3 镜，时长不固定（引导值）
4. 2D 站位图：**v1 不做**（仅结构化文本 blocking），v2 再评估
5. 四视图：角色变体产出 **1 张四视图合成图**
6. 段内各分镜时长之和 = 段目标时长（引导）
7. 首帧槽位：有首帧时默认占图1
8. 合成：v1 接受"无配音半成品"，仅拼接+转场（含归一化）
9. 图片槽位：提示词统一用 **`@图N`** 引用
10. 首尾帧：**支持**，默认走首尾帧锚定
11. 平台提示词：v1 只做**通用默认模板**，豆包/即梦专属模板留口子后续补
12. 配音/字幕：**后续版本**做

**待确认（v1 先按默认走，不阻塞开发）**
1. 平台实测细节：多分镜上限、`@` 是否被识别、首尾帧入口、图片顺序影响
2. 阿里百炼具体模型选型（qwen-max / qwen-plus / qwen3 等）

【基础设定】
日系赛璐璐漫剧风格，细腻描线，电影级布光。9:16竖屏。

【角色一致性（参考图）】

图2=城市广场（白天·全景）
图3=沈清和（四视图）
图4=林晚（四视图）
沈清和：全程保持图3中的脸型、发型、深蓝连帽卫衣、体型完全一致。

禁止换脸、换发型、换服装。

【空间与站位（锁定）】
沈清和位于中景偏左，面朝斜上方45°；林晚位于其右侧约1.5米、画面右侧。
镜头始终处于两人连线的同一侧（不跨越180°轴线）。
本段从图1首帧平滑接续：人物位置、光线方向、色调与首帧一致。
